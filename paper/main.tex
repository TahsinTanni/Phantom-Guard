\title{Advisory Text Is Not Ground Truth: Reporter Coverage, Campaign
Duplication, and a Null Result for Package Naming in GHSA/OSV Malware
Advisories}

\author{\IEEEauthorblockN{Anonymous Author(s)}
\IEEEauthorblockA{Anonymous Institution(s)}}

\maketitle

\begin{abstract}
Advisory databases such as GHSA and OSV are increasingly mined as ground
truth for malware behaviour in package ecosystems. We collect 994
confirmed-malicious PyPI and npm advisory records and show that they
correspond to 498 packages and only 317 independent campaigns (npm 152,
PyPI 165) once cross-source re-reporting, multi-name campaigns and generic
reporter templates are handled. We test whether compound/generic names
(e.g.\ \texttt{py-*}, \texttt{*-tools}) go with a described payload
mechanism. Pooled, the odds ratio (OR) is 1.045 [0.635, 1.721]; adjusted for
ecosystem and reporter coverage, it is 0.741 [0.424, 1.294]. With 0.78 power
at OR 2.0, the data rule out associations of about OR $\geq$ 1.7 in the
positive direction, not only large ones. Reporter coverage predicts the
label far better than naming: Amazon Inspector coverage carries an OR of
about 23. Two annotators validated the labeler ($\kappa$ = 0.78 and 0.66):
precision is 0.917 [0.819, 0.964], but it misses a described mechanism in
0.425 [0.285, 0.578] of sampled negatives; corrected for this, the OR is
1.089 [0.637, 1.869]. A GHSA-only signal seen in a smaller earlier snapshot
does not replicate (OR 1.541, $p=0.096$). The naming grammar flags only 5\% of 139 real
LLM-hallucinated names versus 16--21\% of popular benign packages, so it
does not measure hallucination-proneness. Corpus and code are released.
\end{abstract}

\begin{IEEEkeywords}
software supply chain, malicious packages, security advisories, PyPI, npm,

\end{IEEEkeywords}

\section{Introduction}
\label{sec:intro}

Malicious packages account for 49\% of vulnerability reports in npm and
14\% in PyPI~\cite{akhavani2025}, and LLM code assistants add a
new route to them: a model recommends a package that does not exist, and an
attacker registers the name~\cite{spracklen2024,huang2026}. Measurement work
on this threat increasingly treats the GitHub Security Advisory database
(GHSA) and OSV as ground truth, both for which packages are malicious and
for what the malware does.

This paper checks two assumptions that such work usually makes and rarely
tests. First, that advisory records are independent observations. They are
not: GHSA and OSV re-report the same package under different identifiers,
and one attacker squats many names with one payload. In our corpus, 994
records reduce to 317 campaigns. Second, that a mechanism mentioned in the
advisory text is a property of the malware. It is partly a property of
whoever wrote the advisory: which analysts covered a package changes
whether a mechanism is described at all. Once both are accounted for, the
association we test is absent, and the sample is large enough to bound it.

\textbf{Research question.} Among confirmed-malicious packages, is
compound/generic naming associated with a described payload mechanism,
after accounting for how the advisory was reported?

\textbf{Contributions.}
\begin{enumerate}
\item A frozen, checksummed, campaign-level corpus (994 records
$\rightarrow$ 498 packages $\rightarrow$ 317 campaigns) and a reusable
two-stage collapse that never keys on generic reporter templates.
\item Evidence that mechanism labels mined from advisory text depend
strongly on reporter coverage.
\item A two-annotator labeler validation measuring precision and misses,
and a misclassification-corrected estimate.
\item A null for naming $\rightarrow$ mechanism that excludes moderate
effects, and a negative validation of the naming grammar as a
hallucination proxy.
\end{enumerate}

\section{Background and Related Work}
\label{sec:related}

\textbf{Package hallucination.} Spracklen et al.~\cite{spracklen2024}
measured hallucinated package names across 16 code-generating models and
found the problem persistent across models. Churilov~\cite{churilov2026}
replicated the study on 2026 frontier models and released the set of names
hallucinated by all five models tested, which we use in
Section~\ref{sec:iv}. Huang et al.~\cite{huang2026} registered hallucinated
npm names and observed real installs, which establishes the threat model
behind this work.

\textbf{Malicious-package measurement.} Akhavani et al.~\cite{akhavani2025}
analyse vulnerability reports across ten language ecosystems and find that
malicious packages make up a large share of reported npm and PyPI
vulnerabilities. Guo et al.~\cite{guo2026} benchmark npm malicious-package
detectors on a large labelled set. Hillah et al.~\cite{hillah2026} use PyPI
registration metadata to give a calibrated posterior for
registered-but-suspicious packages. Guo et al.\ note that typosquatting
campaigns reuse identical payloads across many names, but treat each
package as a separate instance; Akhavani et al.\ remove 6,391 duplicate reports and prefer
Snyk text over GitHub advisories because it is more detailed, a
reporter-coverage choice whose effect on estimates they do not measure. We
quantify both.

\textbf{Scope.} Work on hallucinated agent-skill names that host adversarial
prompts~\cite{spira2026} concerns a different artifact and a different
mechanism, and is not studied here.

\subsection{Collection}
We query the GHSA API for advisories of type \texttt{malware} in the pip and
npm ecosystems, newest first, following the API's cursor until each
ecosystem has 250 advisory--package records, and query OSV.dev for each
package found. After removing exact duplicates on (ecosystem, package,
advisory id), the corpus has 994 records (500 GHSA, 494 OSV) for 498
packages (250 PyPI, 248 npm). The pull was made on 5~October 2026. Its GHSA
advisories were published between 21~July and 5~October 2026; npm publishes
so many malware advisories that its half spans only 30~September to
5~October. The pull is frozen to a snapshot with a SHA-256 manifest, and
every number in this paper is computed from that file.

\subsection{Campaign collapse}
\label{sec:collapse}
Fisher's and CMH tests assume independent units, and one npm family alone
has 74 member packages. We collapse in two stages. Stage~1 merges records
of the same (ecosystem, package), which catches GHSA/OSV re-reports.
Stage~2 groups packages by a campaign signature, checked in priority order:
\begin{enumerate}
\item the reporter's own \texttt{Campaign:} identifier, when present (the
kam193 reporter assigns these);
\item otherwise the first 200 characters of the description, after
stripping \texttt{\#\# Source:} headers, masking the package's own name and
masking URLs.
\end{enumerate}
Generic texts are never used as keys, because they are identical across
unrelated incidents: GHSA's ``should be considered fully compromised''
boilerplate, kam193's generic install-time pentest template, Amazon
Inspector's one-line ``was found to contain malicious code'' verdict, and
advisories whose only text is an OpenSSF credit link. Packages carrying
only such text stay as their own unit. A unit counts as grammar-flagged, or
as DV-positive, if any member does, since names within one campaign can
differ in their grammar flag. An audit of near-identical signatures
motivated the last two template rules and the URL mask.

The result is 498 packages $\rightarrow$ 317 campaigns (npm 152, PyPI 165),
of which 277 have a single member. The largest are two WhatsApp-library
fork families of 74 and 15 npm names and an 11-name PyPI campaign.

\subsection{Independent variable: compound/generic naming}
\label{sec:iv}
A name is flagged if it contains a token from lists of compound suffixes,
compound prefixes or trend suffixes (e.g.\ \texttt{py-}, \texttt{-tools},
\texttt{-client}, \texttt{-sdk}). The classifier reads the name only. The
grammar was designed as a proxy for names an LLM might hallucinate, so we
tested it against real hallucinations (Table~\ref{tab:grammar}). It flags
7 of the 139 names that all five models in Churilov's
study~\cite{churilov2026} hallucinated, against 16--21\% of the top-5,000
benign packages. We therefore describe the variable as compound/generic
naming, which is what it measures. The benign sets must be chosen with
care: an npm control drawn from search-API results for common terms is
flagged at 73\%, because the search terms are themselves grammar tokens.
Flagged hallucinated names include, e.g., \texttt{aws-cdk} and
\texttt{flask-idempotency}.

\subsection{Dependent variable: described mechanism}
\label{sec:dv}
A first taxonomy, aimed at agent-directed prompt injection, found nothing:
advisory text is third-person analyst narration, not text from the package.
The dependent variable is therefore whether the advisory text describes at
least one of six mechanisms:
\begin{itemize}
\item obfuscated payload execution;
\item a hidden install hook;
\item credential or wallet exfiltration;
\item remote backdoor access;
\item remote payload retrieval;
\item a brand-impersonation narrative.
\end{itemize}
The patterns were first derived from PyPI text and missed npm phrasing;
adding \texttt{postinstall} hooks, JavaScript obfuscators and verbs such as
\emph{reads} and \emph{POSTs} fixed this. A negation guard drops a match
when a cue (\emph{does not}, \emph{do not}, \emph{did not},
\emph{doesn't}, \emph{no evidence of}) occurs within 40 characters before
it, unless \emph{but}, a semicolon or a period intervenes. The labeler's
signature accepts text only, never the name, and a test enforces this. The
text is the union of a package's GHSA and OSV descriptions; GHSA-only text
is a sensitivity analysis (Section~\ref{sec:ghsa}).

\textbf{Validation.} Two authors annotated independently, then adjudicated,
under a written rule: a match counts only if prose, not an analyst tag
list, describes the mechanism. Seeded samples stratified by ecosystem
$\times$ Amazon Inspector coverage gave 60 labeler-positive and 40
labeler-negative campaigns (full text). First-pass $\kappa$ was 0.783 on
positives (96.7\% raw agreement) and 0.658 on negatives (82.5\%). Precision is 55/60 = 0.917 [0.819, 0.964]. All five
false positives are the same kam193 tag-list phrase (``Downloads and
executes a remote executable''), so remote payload retrieval has precision
4/9 while every other category is at 1.00. The miss rate (negatives whose prose
does describe a mechanism) is 17/40 = 0.425 [0.285, 0.578], or 14/40 =
0.350 [0.221, 0.505] counting three borderline rows as correct. Misses
concentrate in npm campaigns with Amazon Inspector text (11 of 15 sampled).
Sending only host fingerprints (hostname, IP, username) fits no category.

\subsection{Reporter coverage}
We parse the \texttt{\#\# Source:} headers in both texts of every package
and merge them per campaign. GHSA's boilerplate and OSV's
\texttt{ghsa-malware} section are the same text and count as one reporter.
Headerless text without boilerplate is \emph{unattributed} (96 of 498
packages). From the parsed headers we derive a reporter count
(\texttt{n\_reporters}) and three indicators: kam193, amazon-inspector and
boilerplate.

\subsection{Analysis}
\label{sec:analysis}
We use Fisher's exact test on the pooled and per-ecosystem $2\times2$
tables, and CMH tests stratified by ecosystem and by ecosystem $\times$
reporter count~\cite{agresti}. We fit the logistic regression
$\mathit{DV} \sim \mathit{grammar} + \mathit{ecosystem} +
\mathit{n\_reporters} + \mathit{amazon\_inspector}$ (model~d), and three
variants: (a)~without the Amazon term, (b)~without the reporter count, and
(c)~(a) plus the boilerplate and kam193 indicators. ORs come with Woolf,
Robins--Breslow--Greenland or Wald 95\% CIs as appropriate. Power at the
achieved $n$ follows Hsieh et al.~\cite{hsieh1998}. We correct the pooled OR
for outcome misclassification by predictive-value
back-calculation~\cite{lash2009}: per grammar row, true positives =
positives $\times$ precision + negatives $\times$ miss rate (0 for
no-text campaigns). This assumes equal predictive values across rows, as
the samples suggest (precision 0.95 vs.\ 0.90, miss rate 0.38 vs.\ 0.44).
The interval uses 20,000 Jeffreys Beta draws plus random error.

\subsection{Main test}
The pooled table is $[[46,39],[123,109]]$, which gives OR 1.045 [0.635,
1.721], $p=0.899$ (Table~\ref{tab:main}). Adjusting for ecosystem with CMH
gives 1.046 [0.635, 1.722], $p=0.860$.

\subsection{Adjusted}
In model~(d) the grammar OR is 0.741 [0.424, 1.294], $p=0.292$, with a
variance inflation factor of 1.02. Reporter coverage explains the label
instead. Amazon Inspector coverage has OR 23.1 in model~(d) and 22.9 in
model~(b); entered without it, the reporter count has OR 4.05 (model~a).
With both terms in the model (variance inflation factors at most 1.94), the
reporter count falls to 0.99, and model~(d) as a whole is significant
(likelihood-ratio $p<10^{-16}$).

\subsection{Misclassification}
The corrected OR is 1.089 [0.637, 1.869], or 1.078 [0.640, 1.826] with the
14/40 miss rate: similar error rates in both rows dilute any effect only
slightly.

\subsection{Text-source sensitivity}
\label{sec:ghsa}
Reading only GHSA's text gives OR 1.541 [0.934, 2.542], $p=0.096$ (CMH
1.557 [0.941, 2.578], $p=0.085$). In an earlier snapshot of 105 campaigns
the GHSA-only CMH estimate was 2.869 [1.085, 7.583], $p=0.027$; that signal
did not replicate. A single-source estimate depends on which reporter's
text is dropped.

\subsection{Power}
With 26.8\% of campaigns flagged and a baseline DV rate of 0.53 among
unflagged campaigns, the design has 0.78 power at OR 2.0, 0.99 at OR 3.0
and 0.36 at OR 1.5. Reaching 80\% power at OR 2.0 needs about 335 campaigns.

\section{Discussion}
\label{sec:discussion}

\textbf{What the null means.} We find no evidence that compound/generic
naming goes with a described mechanism. The pooled interval excludes OR
above 1.72 and below 0.64, and the misclassification-corrected interval
excludes OR above 1.87, so a positive association of about OR 1.7--2 or
more is unlikely. Effects near OR 1.5 cannot be excluded (power 0.36); a
cost-minimising attacker model~\cite{allodi2022} could motivate only such
a small effect.

\textbf{What the reporter finding means for others.} Any study that uses
GHSA or OSV text as a behavioural label inherits a reporter-coverage
confound: here, one reporter's coverage moves the label rate from 0.10 to
0.66. Dropping OSV's text moved our estimate from 1.05 to 1.54, and to
2.44 in the earlier snapshot. We recommend using the union of the source
texts, parsing reporter sections and controlling for reporter coverage.

\textbf{Why we do not claim ``hallucination''.} The grammar flags 5\% of
real hallucinations, most of them import or module names used as package
names (e.g.\ \texttt{objc}), so it measures generic naming. The gradient from
16--21\% (benign) to 27\% (malware campaigns) is descriptive, and the sets
are not matched.

\section{Threats to Validity}
\label{sec:threats}

\textbf{Construct.} The labeler is a regex taxonomy. Two annotators
validated it ($\kappa$ = 0.783 and 0.658) before adjudication. Recall was
measured: it misses mechanisms in about four of ten sampled negatives,
mostly in Amazon Inspector's npm prose, and host-fingerprint sending has no
category; the corrected OR bounds the effect. Annotators saw package
names. The grammar is validated only as a measure of
generic naming, not of hallucination.

\textbf{Internal.} Reporter coverage is modelled but not exhausted: 96 of
498 packages are unattributed. Grouping rules were revised as audits
surfaced merge failures (142 $\rightarrow$ 106
$\rightarrow$ 94 $\rightarrow$ 93 $\rightarrow$ 105 campaigns on the earlier
snapshot, with OR 0.884, 0.964 and 0.812 at the last three), and further
under-merging is possible; merging the 13 template packages leaves the
estimate null.

\textbf{External.} GHSA advisories in the corpus were published between
21~July and 5~October 2026, and the npm half spans six days. The corpus
covers two ecosystems and 317 campaigns.

\textbf{Statistical.} The design has 0.36 power at OR 1.5, several strata
are sparse, and CMH assumes a homogeneous OR across strata.

% ---------------------------------------------------------------------------
\section{Conclusion and Future Work}
\label{sec:conclusion}

Advisory records are not independent, and advisory text is not ground
truth. After correcting for both, compound/generic naming shows no
association with described malware mechanisms at a sample size that rules
out moderate effects, while reporter coverage does. Next steps are a
longer npm collection window; extending the labeler to Amazon Inspector's
npm phrasing, ignoring tag lists and adding a host-fingerprint category; a
matched benign comparison; and a hallucination instrument based on import
names rather than naming grammar.

\textbf{Artifact availability.} The frozen snapshot, manifests, annotation
sheets, analysis code and tests are available at [anonymized]. GHSA
advisory data are licensed CC BY 4.0, OSV records carry per-source
licences, and the hallucinated-name set~\cite{churilov2026} is CC BY 4.0.
